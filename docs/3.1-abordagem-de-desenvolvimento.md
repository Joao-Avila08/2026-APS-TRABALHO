O projeto segue uma abordagem **incremental**, na qual o documento é desenvolvido por partes, seguindo uma ordem de produção. Primeiro são levantados os requisitos e as informações necessárias sobre o sistema, depois são desenvolvidos os modelos, as funcionalidades e, por fim, é feita a revisão do projeto como um todo.

Ao final de cada ciclo, a parte produzida é conferida para verificar se está correta e se está de acordo com as demais seções do documento. Após a conferência, a versão atualizada é registrada no repositório do projeto. As partes mais importantes também podem ser apresentadas ao cliente durante o desenvolvimento, permitindo verificar se o projeto está seguindo o que foi solicitado.

Essa abordagem foi escolhida por ser mais adequada a um projeto desenvolvido individualmente. Diferentemente do modelo **cascata**, que concentra as etapas em uma sequência mais rígida e dificulta alterações depois que uma etapa foi concluída, a abordagem incremental permite revisar e melhorar partes do projeto durante seu desenvolvimento. Apesar de utilizar algumas ideias presentes no Scrum, como trabalhar em ciclos e revisar o que foi produzido, não são utilizadas práticas voltadas para equipes, como reuniões diárias, divisão de papéis e planejamento de sprints com vários integrantes, pois o projeto é realizado individualmente.
